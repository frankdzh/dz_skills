# OpenAI 官方行为基线（社区采信版）

> 用途：probe_openai.py 字段类判据的实证锚点。采信强度分级，
> 「确证」级结论仅使用强锚点；弱锚点只支撑「疑似，待复核」。
> 采信日期：2026-10-18。

## 采信来源与强度

| 来源 | 强度 | 说明 |
|---|---|---|
| OpenAI 官方 API 参考（developers.openai.com，2026-10 版）chat completions create 页真实示例 | **强（一手）** | 示例含真实形态 ID 与流式序列 |
| LiteLLM 源码（github.com/BerriAI/litellm） | **强（一手）** | 适配层生成 ID 的直接实证 |

## 锚点清单

### 1. 响应 ID 格式（强锚点）

- 官方真实示例（文档原文）：
  - `chatcmpl-B9MBs8CjcvOU2jLn4n570S5qMJKcT`
  - `chatcmpl-B9MHDbslfkBeAs8l4bebGdFOJ6PeG`
- 形态：**base62（大小写字母+数字），约 28 字符，无连字符**
- **UUID 形式（8-4-4-4-12 连字符）= 适配层生成**：LiteLLM proxy 源码
  `from uuid import uuid4` 直接实证；本机实测两个独立中转端点
  （多个中转站）均返回 UUID 形 `chatcmpl-`
- 判定语义：UUID 形 → 「非官方直连（适配层生成 ID）」——渠道线索，
  **不证伪后端模型家族**（LiteLLM + 官方 key 的自用网关同样如此）

### 2. system_fingerprint（强锚点）

- 官方示例：`fp_44709d6fcb`（`fp_` + hex）
- 文档标注 optional；部分模型合法返回 null（openai-openapi issue #167）
- 流式场景**每个 chunk 均携带同一值**
- 判定语义：仅观察项——官方可为 null、仿冒可随手伪造，无判别力

### 3. 流式序列规范（强锚点）

文档明确（streaming-events 页 + 示例）：

- 每个 chunk 的 `id` 相同（"Each chunk has the same ID"）
- `finish_reason` 仅在最后的内容 chunk 非空
- 末尾 chunk（`stream_options.include_usage` 时）`choices` 为空数组 + `usage`
- 序列以 `data: [DONE]` 终止

判定语义：缺 `[DONE]` 或 chunk ID 不一致 → 偏离（有官方文档锚点）

### 4. usage 形状（强锚点）

- 在场时 `prompt_tokens` / `completion_tokens` / `total_tokens` 必有且
  total = prompt + completion（completion 已含 reasoning）
- `*_tokens_details` 均 optional，官方可合法省略

### 5. logprobs 现状（中锚点：社区帖 + 官方文档"参数支持因模型而异"）

- GPT-5.1/5.2/5.3-codex/5.4：`top_logprobs` 单独传 → 200 但不返回；
  ≥2 → 可复现 500（社区实测表）
- 推理模型（o 系）：400 `unsupported_parameter` 为官方规范行为
- 4o / 4.1 / 4o-mini：正常返回 top_logprobs

### 6. model 回显（强锚点）

- 当前世代官方命名（文档示例）：`gpt-6-astra`、`gpt-6-sol` —— **无日期后缀**
- 判定语义：家族比对（声称 vs 回显），不验快照格式

## 判据使用规则

| 证据类型 | 允许的结论措辞 |
|---|---|
| 跨家族替换（model 回显异于声称家族） | 「已确证」（逻辑铁证，不依赖本基线） |
| UUID 形 ID、[DONE] 缺失、chunk ID 不一致（强锚点） | 「偏离（有官方文档锚点）」，仍区分「非官方直连」≠「模型掺水」 |
| logprobs 未返回（中锚点，非推理 openai 系） | 「疑似，待复核」 |
| system_fingerprint 缺失 | 不作判据（观察项） |

## 局限声明

本基线为文档 + 社区采信，未经本机对官方端点的直接实测（那需 $5 充值）。
若官方行为与文档示例出现漂移（OpenAI 历史上发生过），强锚点判据可能
产生误报——遇到「全部强锚点同时偏离」且无家族铁证的端点，优先怀疑
基线漂移，去官方文档复核后再下结论。
