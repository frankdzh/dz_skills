# 多智能体会话日志模糊与语义检索技能设计与实现规范

## 1. 需求背景与核心价值

在大师日常使用多款 AI 编程智能体（如 Antigravity、OMP、Claude Code、Codex、Pi、Cursor 等）进行高强度研发的过程中，经常遇到以下高频痛点：
1. **记忆模糊**：“记得前几天/上周讨论过某个 Bug、架构设计或支付回调接口，但记不清具体是哪个智能体、哪一次会话中处理的”。
2. **时间跨度受限**：原 `workday-recall` 技能主要面向“昨天~今天”的早晨开工接续，时间窗口被硬编码为昨日收官，无法灵活向历史回溯或跨自定义时间段查找。
3. **缺乏深层语义与模糊检索**：传统的全量 `grep` 缺少时间维度过滤、无法解析复杂的 JSONL/SQLite 异构存储结构、不能理解中英文同义近义词，且极易因超长工具日志造成终端刷屏。

本技能通过**“灵活时空窗口 + 异构日志解析 + 内存 FTS5 倒排 + 本地混合语义重排”**，实现**零常驻后台服务（Zero-Daemon）、零外部向量 API 依赖（Zero-API）、毫秒级极速响应**的全域会话日志模糊检索。

## 2. 核心架构与三层渐进流水线 (Pipeline)

```
[用户输入: 搜索关键词 + 自然语言时间范围]
                     │
                     ▼
┌────────────────────────────────────────────────────────┐
│ 第一层：灵活时空窗口解析层 (Time-Window Filter)         │
│ - 相对时间：今天、昨天、最近3天(3d)、7天内(7d)、本周等    │
│ - 绝对范围：2026-10-15、2026-10-15..2026-10-20         │
│ - 零依赖快速时区换算，先剔除 90% 不在时间窗内的历史文件   │
└──────────────────────────┬─────────────────────────────┘
                           │ 候选会话元数据流
                           ▼
┌────────────────────────────────────────────────────────┐
│ 第二层：FTS5 倒排与轻量穿透层 (BM25 Screening)          │
│ - 进程内 SQLite :memory: FTS5 倒排表，毫秒级快速召回   │
│ - 默认快搜：会话主题、首末用户指令、收官意图与进展产出   │
│ - `--deep` 模式：流式按行穿透扫描底层 transcript.jsonl │
│   匹配具体工具调用命令、修改文件与执行输出             │
└──────────────────────────┬─────────────────────────────┘
                           │ 粗排候选切片 (Top N)
                           ▼
┌────────────────────────────────────────────────────────┐
│ 第三层：混合语义重排与上下文提纯 (Semantic Re-ranking) │
│ - 优先使用本地 sentence-transformers 计算余弦语义相似度│
│ - 无模型或首次冷启动时，自动降级为内置“词元语义加权算法”│
│ - 提取命中前后 2 轮上下文，高亮匹配词，剥离机器套话    │
└────────────────────────────────────────────────────────┘
```

## 4. 命令行交互与参数规范

### 4.1 CLI 命令定义
脚本路径：`transcript-search/scripts/search_agent_logs.py`

```bash
python3 search_agent_logs.py [QUERY] [OPTIONS]
```

### 4.2 参数列表
- `QUERY`：搜索关键词或自然语言短语（支持空格分词多关键词）。
- `--since <TIME_SPEC>`：起始时间，支持 `today`、`yesterday`、`3d`、`7d`、`30d`、`2026-10-15`（默认：`7d`）。
- `--until <TIME_SPEC>`：结束时间，支持同上格式（默认：当前时刻 `now`）。
- `--project <PATH_OR_NAME>`：限定工作区（默认搜全域，但置顶当前项目；传入路径时只搜该项目）。
- `--agent <NAME>`：限定智能体名称（如 `antigravity`、`claude`、`codex` 等，默认搜索全部）。
- `--deep`：启用深度穿透，扫描底层 `transcript.jsonl` 中的详细工具调用与助手长文。
- `--semantic / --no-semantic`：是否启用语义相似度重排（默认自动启用）。
- `--limit <N>`：最多展示的会话结果数量（默认：`10`）。
- `--json`：以标准 JSON 结构输出原始数据，便于下游工具消费。

## 6. 性能防护与边界兜底策略

1. **零常驻守护进程**：无后台 Daemon，无端口监听，执行即启动，输出即退出。
2. **大文件流式保护**：单文件超过 20MB 时采用逐行生成器，单文件最大扫描上限 1.5 秒，防止极端大日志拖慢检索。
3. **优雅降级与网络无关**：无外部模型时不调用网络，无本地 embedding 库时自动使用内置 Jaccard + N-gram 相似度算法，确保 100% 离线高可用。
4. **隐私与脱敏防护**：自动过滤搜索命中上下文中的 API Key、Token、私钥和密码。

## 7. 测试与验收方案

1. **单测套件**：
   - 时间解析器测试（覆盖相对/绝对时间跨度）。
   - FTS5 内存检索测试（多关键词、空格分隔、大小写不敏感）。
   - 本地语义评分与优雅降级测试（验证无模型环境下的稳定性）。
2. **端到端测试**：
   - 在真实本地日志（Antigravity / Claude / Codex / OMP）中检索关键词，验证高密度看板渲染正确、耗时 < 1 秒。
